## 快速开始

### 安装与启动

本工具是一个 Streamlit Web 应用，运行在本地。启动方式:

```bash
cd "C:/Users/lenovos/Regression Analysis"
uv run streamlit run app/app.py
```

启动后，浏览器会自动打开 http://localhost:8501，进入应用主页。

### 支持的数据格式

| 格式 | 扩展名 | 编码 | 说明 |
|------|--------|------|------|
| CSV | `.csv` | UTF-8 / GBK 自动检测 | 推荐格式 |
| TSV | `.tsv` | UTF-8 / GBK | 制表符分隔 |
| TXT | `.txt` | UTF-8 / GBK | 逗号或制表符分隔 |
| Excel | `.xlsx` / `.xls` | N/A | 支持多 sheet（默认第一个） |

**文件大小限制**: 50 MB 以上发出警告，200 MB 以上阻止上传。

### 五个页面

工具包含五个功能页面，按工作流顺序排列:

1. **数据上传与预览** — 上传文件、查看数据摘要、管理变量类型
2. **数据探索** — 描述性统计、相关矩阵、分布图、缺失值处理、异常值检测
3. **模型设定** — 选择变量、配置模型、变量转换、交互项、运行回归
4. **回归结果** — 系数表、统计量、诊断图、多模型对比、假设检验
5. **导出与报告** — CSV/Excel/PNG/SVG/LaTeX/HTML/ZIP 多格式导出

## 界面概览

每个页面遵循统一布局:

## 案例 1: 房价影响因素分析

### 场景描述

某房地产研究团队需要分析影响房屋价格的关键因素。数据包含 500 套房屋的记录，变量包括面积、卧室数、房龄、位置评分、楼层、是否有车库等。

本案例将演示从数据加载到报告导出的完整流程。

### 步骤 1: 加载数据

1. 打开应用，进入 **数据上传与预览** 页面。
2. 点击 **加载快速示例数据集** 按钮（蓝色按钮，位于上传区域下方）。
3. 系统自动生成一个包含 500 行 8 列的模拟数据集。

**预期结果**:
- 页面右侧显示 "示例数据集已加载！"
- 显示数据摘要卡片: 行数 500、列数 8、内存占用量、编码 "N/A (模拟数据)"
- 下方展开 "变量信息" 按钮可查看每个变量的推断类型

> **[截图占位]**: 数据上传页面，右侧显示数据摘要卡片（行数、列数、内存、编码）和变量信息表。左侧显示文件上传区域和"加载快速示例数据集"按钮。

### 步骤 2: 数据探索

1. 切换到 **数据探索** 页面。
2. 查看 **描述性统计** 表格，了解各数值变量的均值、标准差、极值。
3. 查看 **相关系数矩阵** 热力图，了解变量间的线性相关程度。

**预期结果**:
- 描述性统计表显示 price、sqft、bedrooms、age 等变量的统计量
- 相关系数热力图以红蓝色阶显示变量间相关度（红色=正相关，蓝色=负相关）
- 可观察到 sqft 与 price 有较强的正相关

> **[截图占位]**: 数据探索页面，显示相关系数矩阵热力图（红蓝色阶，标注皮尔逊相关系数值）。

4. 在 **分类变量频率** 区域，选择 "bedrooms" 查看卧室数的分布饼图。

### 步骤 3: 模型设定

1. 切换到 **模型设定** 页面。
2. 在 **变量选择** 区域:
   - **因变量**: 选择 `price`（房价）
   - **自变量**: 勾选 `sqft`（面积）、`bedrooms`（卧室数）、`age`（房龄）、`location_score`（位置评分）、`floor`（楼层）、`has_garage`（是否有车库）
3. 在 **模型选项** 区域，保持默认设置:
   - 包含常数项: 是
   - 置信水平: 95%
   - 标准误类型: 普通标准误
   - 缺失值处理: 删除缺失行
4. 页面底部显示公式预览: `price ~ sqft + bedrooms + age + location_score + floor + has_garage`
5. 点击 **运行回归** 按钮。

**预期结果**:
- 显示 "回归模型运行成功！"
- 快速摘要显示 R-squared、Adj. R-squared、观测数
- 出现 "查看回归结果" 链接

> **[截图占位]**: 模型设定页面，变量选择器展开，因变量选择 price，多个自变量已勾选。底部显示公式预览和"运行回归"按钮。

### 步骤 4: 解读结果

1. 点击 "查看回归结果" 链接，或手动切换到 **回归结果** 页面。

#### 4.1 模型统计量

页面顶部显示模型统计量卡片:

| 指标 | 含义 | 期望范围 |
|------|------|---------|
| R² | 模型解释力 | 0-1，越高越好 |
| Adj. R² | 考虑变量数量的调整 R² | 0-1，越接近 R² 越好 |
| F 统计量 | 模型整体显著性 | p < 0.05 表示显著 |
| RMSE | 预测误差均方根 | 越小越好 |
| AIC / BIC | 模型信息准则 | 越低越好（模型对比用） |
| Log-Likelihood | 对数似然值 | 越高越好 |

**预期结果**:
- R² 约为 0.7-0.8（模拟数据，较高）
- F 统计量 p 值远小于 0.001

> **[截图占位]**: 模型统计量卡片网格，显示 R²、Adj-R²、F 统计量、N、AIC、BIC、Log-Likelihood、RMSE 八项指标。

#### 4.2 系数表解读

系数表以表格形式展示每个自变量的回归系数:

| 列名 | 含义 |
|------|------|
| 变量 | 自变量名称 + 显著性标记 |
| 系数 | 偏回归系数（其他变量固定时的边际效应） |
| 标准误 | 系数估计的标准误差 |
| t 值 | 系数的 t 检验统计量 |
| p 值 | 双侧检验的 p 值 |
| 95% CI | 95% 置信区间 |
| 显著性 | `***` p<0.01, `**` p<0.05, `*` p<0.1 |

**如何解读**:
- `sqft` 的系数（如 200）表示: 其他条件不变时，面积每增加 1 平方英尺，房价平均增加约 200 元
- p<0.01 的变量标 `***`，表示在 1% 水平上显著
- 绿色高亮行 = p<0.05，深绿色 = p<0.01

> **[截图占位]**: 系数表格，绿色/深绿色高亮显著变量，显著性星标清晰可见。

#### 4.3 模型摘要

展开 "模型摘要" 区域，查看自动生成的中文分析文本:

> 本研究报告了 OLS 回归结果，因变量为「price」。模型整体显著(F(6,485)=xxx.xx, p<0.001)。R²=0.xxxx，调整R²=0.xxxx，RMSE=xxxx.xx。AIC=xxxx.xx，BIC=xxxx.xx。有效样本量 N=492。

#### 4.4 诊断图

页面下半部分提供 5 个诊断图标签页:

- **散点图 + 回归线**: 展示因变量与单个自变量的关系
- **残差 vs 拟合值**: 检验线性假设和等方差性（散点均匀分布=良好）
- **Q-Q 图**: 检验残差正态性（点沿对角线分布=正态）
- **尺度-位置图**: 检验等方差性（平滑线水平=方差一致）
- **Cook's Distance**: 识别影响点（红色柱超过阈值=可能的异常点）

展开 "诊断总览面板 (2x2)" 可同时查看四个核心诊断图。

> **[截图占位]**: 诊断总览面板的 2x2 网格，包含残差图、Q-Q 图、尺度-位置图和 Cook's Distance 图。

### 步骤 5: 导出报告

1. 切换到 **导出与报告** 页面。
2. 在 **数据导出** 区域下载 CSV 或 Excel 格式的数据。
3. 在 **结果导出** 区域下载系数表（CSV/Excel）和模型摘要文本。
4. （可选）在回归结果页面点击 "保存为 PNG" 暂存诊断图，回到导出页面下载 PNG/SVG 格式图表。
5. 点击 **一键导出所有结果** 生成包含系数表、摘要和图表在内的综合 ZIP 包。

**导出格式汇总**:

| 导出类型 | 格式 | 用途 |
|---------|------|------|
| 数据 | CSV / Excel | 保存处理后的数据 |
| 系数表 | CSV / Excel | 用于论文表格制作 |
| 模型摘要 | TXT | 文本报告 |
| 诊断图 | PNG / SVG | 论文插图 |
| 综合报告 | ZIP | 所有结果打包 |
| LaTeX 表格 | .tex | 直接插入 LaTeX 论文 |
| HTML 报告 | .html | 自包含网页报告 |
| 复现包 | ZIP | 数据 + 配置 + reproduce.py |

## 案例 2: 员工满意度调查

### 场景描述

某企业 HR 部门进行员工满意度调查，收集了 400 名员工的数据，包括工资、教育水平、工作经验、性别、行业、周工时、司龄等信息。分析目标是:
1. 识别满意度的影响因素
2. 比较不同变量组合的模型
3. 探索教育水平与工作经验的交互效应
4. 使用稳健标准误处理可能的异方差

### 步骤 1: 加载工资数据

1. 在 **数据探索** 页面的左侧边栏中，找到 **示例数据** 区域。
2. 选择 "工资数据 (400行, 7列)"。
3. 点击 **加载** 按钮。

**预期结果**:
- 侧边栏显示 "已加载「工资数据」！"
- 页面中央显示描述性统计和相关系数矩阵

### 步骤 2: 处理缺失值

1. 在 **缺失值处理** expander 中查看缺失情况。
2. 数据中 `years_at_company` 列有 5 个缺失值（约 1.25%）。
3. 选择处理策略 "中位数填充 (Median)"。
4. 点击 **应用缺失值处理**。

**预期结果**:
- 显示 "缺失值处理完成！"
- 显示处理前后行数变化: 400 行 → 400 行（中位数填充不删除行）
- 缺失值由 5 个变为 0

> **[截图占位]**: 缺失值处理 expander，显示缺失分析表和策略选择器。

### 步骤 3: 运行多个模型进行对比

#### 模型 A: 基准模型

1. 切换到 **模型设定** 页面。
2. 变量选择:
   - **因变量**: `satisfaction`（满意度）
   - **自变量**: `income`（收入）、`education`（教育）、`experience`（经验）
3. 点击 **运行回归**。

**预期结果**: R² 约 0.3-0.4，income 和 education 显著。

#### 模型 B: 加入更多控制变量

1. 在 **多模型对比** 区域，点击 "添加对比模型"。
2. 在对比模型 1 中:
   - **因变量**: `satisfaction`
   - **自变量**: `income`、`education`、`experience`、`is_urban`（城市/农村）、`spending`（消费支出）
3. 点击 **运行所有模型**。

**预期结果**:
- 两个模型对比表显示: 模型 B 的 R² 应高于模型 A（加入更多变量后解释力提升）
- 但 Adj-R² 的提升幅度较小（新变量贡献有限）

> **[截图占位]**: 多模型对比系数表，两列分别显示模型 A 和模型 B 的系数（含标准误和显著性星标）。

### 步骤 4: 添加交互项

1. 保持变量选择不变。
2. 展开 **变量转换** expander。
3. 在交互项区域，选择 `income` 和 `education` 创建交互项。
4. 观察公式预览更新: `satisfaction ~ income + education + ... + income:education`
5. 点击 **运行回归**。

**解读交互项**: 如果交互项系数显著为正，说明教育水平越高，收入对满意度的正向效应越强（即高学历者收入增加带来的满意度提升更大）。

> **[截图占位]**: 变量转换 expander，显示交互项创建界面（两个下拉选择框 + 添加按钮）。

### 步骤 5: 使用稳健标准误

1. 在 **模型选项** 区域，将 "标准误类型" 从 "普通标准误" 改为 "HC1 (异方差稳健)"。
2. 重新运行回归。
3. 对比普通标准误与 HC1 标准误的差异:
   - 如果两者接近 → 无异方差问题
   - 如果 HC1 标准误明显更大 → 存在异方差，应使用稳健标准误

**预期结果**:
- 回归结果页面顶部显示 "标准误类型: HC1 (异方差稳健)"
- 系数表中标准误列的值可能相比普通标准误有变化

> **[截图占位]**: 模型控制面板，标准误类型下拉选择器展开，显示 HC0/HC1/HC2/HC3 选项。

### 步骤 6: 异常值检测

1. 回到 **数据探索** 页面。
2. 展开 **异常值检测** expander。
3. 选择数值变量 `income`、`spending`、`satisfaction`。
4. 检测方法选择 "IQR"（默认 1.5 倍）。
5. 勾选 "显示异常值行"。
6. 点击 **运行异常值检测**。

**预期结果**:
- 检测结果表显示每个变量的异常值数和异常率
- 勾选了 "显示异常值行" 后，下方表格高亮显示异常数据

## 案例 3: 政策效果评估

### 场景描述

政策分析师需要评估环境规制政策对工业污染减排的实际效果。数据包含 300 个地级市的横截面数据， 核心变量包括政策执行强度、人均 GDP、工业增加值占比、人口密度和所在区域。分析目标是:
1. 对偏态变量进行对数变换
2. 对连续变量进行中心化处理以增强交互项的可解释性
3. 检验多重共线性 (VIF)
4. 使用 Sample Gallery 快速预览类似场景

### 步骤 1: 使用 Sample Gallery 加载政策评估场景

1. 在 **数据上传与预览** 页面，向下滚动到 "示例数据分析场景库 (Sample Gallery)" 区域。
2. 浏览 5 个预设场景的卡片。
3. 找到 **环境规制政策减排效果评估** 卡片。
   - 标签: 政策评估、交互项、稳健标准误
   - 描述: 300 个地级市面板数据，含政策强度与产业结构交互项及地区固定效应
4. 点击卡片上的 **加载此场景** 按钮。

**预期结果**:
- 页面自动跳转到回归结果页面
- 顶部显示蓝色信息框 "示例数据，仅供功能演示 — 环境规制政策减排效果评估"
- 展开 "分析场景说明" 可阅读完整的分析叙事
- 展开 "本场景特点" 可查看场景的技术特征
- 系数表、统计量、诊断图全部自动生成

> **[截图占位]**: Sample Gallery 卡片网格，5 个场景卡片展示标题、描述和标签。鼠标悬停在"环境规制政策减排效果评估"卡片上。

### 步骤 2: 查看预计算模型结果

Gallery 场景已预计算 OLS 回归结果 (HC1 稳健标准误):

1. 查看 **模型统计量**: R-squared 约 0.59，说明政策变量和产业结构解释了约 59% 的减排变异。
2. 查看 **系数表**: 关注交互项 `policy_intensity:industrial_share` 的系数和显著性。
3. 查看 **系数可视化** 的 dot-whisker 图: 交互项的置信区间是否跨过零点。
4. 查看 **统计诊断** 区域:
   - VIF 诊断结果（检查各变量的 VIF 值）
   - Shapiro-Wilk 正态性检验
   - Durbin-Watson 自相关检验

> **[截图占位]**: 回归结果页面，系数 dot-whisker 图显示各变量的点估计和 95% 置信区间，交互项系数标红。

### 步骤 3: 手动添加变量转换

切换到 **模型设定** 页面，应用变量转换:

1. 展开 **变量转换** expander。
2. **对数变换**: 对 `gdp_per_capita` 应用 "log" 变换（收入变量通常右偏）。
3. **中心化**: 对 `policy_intensity` 应用 "center" 变换。
   - 中心化后，主效应表示在 `industrial_share` 均值处的边际效应
   - 这使交互项系数的解读更加直观
4. **对 `industrial_share` 也进行中心化**。
5. 观察公式预览更新:
   ```
   emission_reduction ~ center(policy_intensity) + log(gdp_per_capita) + center(industrial_share) + population_density + C(region)
   ```
6. 点击 **运行回归** 重新计算。

**对数变换的目的**: 将右偏分布的变量（如 GDP、人口密度）转换为近似正态，改善模型拟合和残差分布。

> **[截图占位]**: 变量转换 expander，每个变量旁有下拉选择框（无变换/对数/标准化/中心化/平方项）。

### 步骤 4: VIF 诊断与共线性检查

在 **回归结果** 页面的 **统计诊断** 区域:

1. 查看 VIF 诊断结果:
   - VIF < 5: 无严重共线性（正常字体）
   - VIF 5-10: 中等共线性（橙色警告）
   - VIF > 10: 严重共线性（红色警告，建议处理）

## 常见问题

### Q: 数据上传后显示乱码怎么办？
A: 工具自动检测 UTF-8 和 GBK 编码。如果自动检测失败，请用记事本或其他编辑器将 CSV 文件另存为 UTF-8 编码后重新上传。

### Q: 变量类型检测不准确怎么办？
A: 在数据上传页面的 "手动覆盖变量类型" expander 中，可以为每个变量重新指定类型（连续/分类/二元/ID/文本/有序）。

### Q: 为什么某些变量没有被加载到自变量选项中？
A: 被检测为 `id` 或 `text` 类型的变量会自动从候选列表中排除。如需使用这些变量，请先在数据上传页手动覆盖其类型。

### Q: R² 很高 (如 > 0.95) 是否意味着模型很好？
A: 不一定。极高的 R² 可能暗示过度拟合或变量间存在数学恒等关系。建议检查 VIF 诊断、Q-Q 图和残差图。

### Q: R² 很低 (如 < 0.1) 是否意味着分析失败？
A: 不一定。某些领域（如心理学、社会学调查数据）R² < 0.1 是常见现象。关键是看 F 检验是否显著，以及个别变量的系数是否显著。

### Q: 图表 PNG 导出失败？
A: PNG 导出依赖 kaleido 库。如果导出失败，请确保已安装:
```bash
uv pip install kaleido>=1.3.0
```
SVG 导出不依赖 kaleido，可作为替代方案。

### Q: 如何保存分析进度？
A: 工具的会话状态会在关闭浏览器后自动保存（JSON 序列化到 .session_cache）。重新打开浏览器时会提示恢复。如需长期保存，请使用导出功能下载数据和结果。

### Q: 为什么 "is_urban" 变量显示为 binary 类型？
A: 变量类型检测器会识别仅有两个唯一整数值（如 0 和 1）的列为二元变量。这是正常的。分类变量（如 "education" 有 5 个水平）会被识别为 categorical。

### Q: 交互项的主效应必须包含吗？
A: 是的。工具在添加交互项时，会自动保留主效应变量。这是计量经济学的标准做法，避免了遗漏变量偏误。

## 第8章 Logit 回归

Logit 回归（又称逻辑回归、Logistic 回归）是本工具支持的第二种回归模型，专用于分析**二分类因变量**。本章将系统介绍 Logit 回归的原理、操作方法和结果解读。

### 8.1 什么是 Logit 回归

#### 什么时候用 Logit 而不是 OLS

| 场景 | 因变量类型 | 示例 | 适用模型 |
|------|-----------|------|---------|
| 预测房价 | 连续值（如 50 万、80 万） | `price ~ sqft + bedrooms` | OLS |
| 预测客户流失 | 二分类（0=未流失, 1=流失） | `churn ~ age + income` | **Logit** |
| 预测考试通过 | 二分类（0=未通过, 1=通过） | `pass ~ study_hours + attendance` | **Logit** |
| 预测患病风险 | 二分类（0=未患病, 1=患病） | `disease ~ age + smoker` | **Logit** |
| 预测满意度评分 | 有序多分类（1-5 分） | `satisfaction ~ income + education` | OLS 或有序 Logit |

**核心区别**:
- **OLS 回归** 预测的是连续数值（如房价 = 200 万），模型形式为 `y = a + b*x + e`。
- **Logit 回归** 预测的是事件发生的**概率**（介于 0 到 1 之间），模型形式为 `log(p/(1-p)) = a + b*x`，即对"几率 (odds) 的对数"建模。

#### 为什么不能用 OLS 处理二分类变量

如果强行用 OLS 处理 0/1 因变量，会出现三个严重问题:
1. **预测值超出 [0, 1] 区间** — 模型可能预测出 -0.3 或 1.5 这样的"概率"。
2. **残差不服从正态分布** — OLS 的正态性假设被违反。
3. **方差不恒定**（异方差） — 二分类变量的方差取决于概率本身。

Logit 回归通过 Sigmoid 函数将线性预测压缩到 (0, 1) 区间，完美解决了这些问题。

### 8.2 在应用中运行 Logit 回归

#### 步骤 1: 加载数据

数据要求: 因变量必须是**二分类变量**（0 或 1）。0 表示"未发生"，1 表示"发生"。

例如: 一份客户流失数据，包含变量 `churn`（0=留存, 1=流失）、`age`、`income`、`education` 等。

#### 步骤 2: 选择模型类型

切换到 **模型设定** 页面，在 **模型选项** 区域找到 **模型类型** 下拉菜单:

- 默认选择为 **OLS**
- 点击下拉菜单，选择 **Logit**

工具提示会显示:

> OLS 适用于连续因变量，Logit 适用于二分类因变量 (0/1)。
> 注意：Logit 模型不支持 F 检验，将使用似然比检验 (LR) 替代。

#### 智能检测与提示

应用会自动检测因变量类型并给出建议:

- **因变量为二分类 + 选择了 OLS**: 显示蓝色信息框，提示 "因变量可能是二分类变量。建议使用「Logit」模型进行逻辑回归。"
- **因变量非二分类 + 选择了 Logit**: 显示黄色警告框，提示 "因变量有 N 个不同值，不适用于 Logit 模型。"

#### 步骤 3: 配置变量与运行

1. 在 **变量选择** 区域指定因变量和自变量（与 OLS 操作相同）。
2. Logit 模型使用最大似然估计 (MLE)，**不需要选择标准误类型**（该选项在 Logit 模式下自动隐藏）。
3. 确认公式预览无误后，点击 **运行回归**。

**预期结果**: 显示 "回归模型运行成功！"，快速摘要展示 Pseudo R²、观测数等信息。

### 8.3 理解 Logit 输出

Logit 回归的输出与 OLS 有显著不同。结果页面展示以下内容:

#### 系数表

| 列名 | 含义 | 与 OLS 的区别 |
|------|------|--------------|
| 变量 | 自变量名称 + 显著性星标 | 同 OLS |
| 系数 | 对数几率变化量 (log-odds) | OLS: 因变量单位的线性变化 |
| OR (Odds Ratio) | 几率比 = exp(系数) | **Logit 独有** |
| 标准误 | 系数估计的渐近标准误差 | OLS: 标准误；Logit: 渐近标准误 |
| z 值 | z 检验统计量 | OLS: t 值；**Logit: z 值** |
| p 值 | 双侧检验的 p 值 | 同 OLS |
| 95% CI | OR 的 95% 置信区间 | OLS: 系数的 CI；**Logit: OR 的 CI** |
| 显著性 | `***` p<0.01, `**` p<0.05, `*` p<0.1 | 同 OLS |

> **重要提示**: Logit 模型使用的是 **z 检验**而非 t 检验。这是因为最大似然估计的系数在大样本下服从正态分布，而不是 t 分布。z 值绝对值 > 1.96 对应 p < 0.05。

#### 模型统计量卡片

Logit 模型展示一套不同于 OLS 的统计量:

| 指标 | 含义 | 判断标准 |
|------|------|---------|
| Pseudo R² (McFadden) | 模型拟合优度（伪 R²） | 0.2-0.4 表示良好拟合 |
| Log-Likelihood | 对数似然值 | 越高越好（模型之间比较） |
| AIC | 赤池信息准则 | 越低越好（模型之间比较） |
| BIC | 贝叶斯信息准则 | 越低越好（惩罚更重） |
| LR chi2 | 似然比检验统计量 | 检验整个模型是否优于空模型 |
| LR p-value | 似然比检验 p 值 | p < 0.05 表示模型整体显著 |

> **注意**: Logit 模型**没有** OLS 中的 R²、Adj-R²、F 统计量、RMSE 和 ANOVA。这些指标依赖于平方和分解，在最大似然估计框架下不适用。

#### 伪 R² (McFadden's Pseudo R²) 解读

McFadden 伪 R² 的定义: `1 - LL_model / LL_null`，其中 LL_model 是当前模型的对数似然值，LL_null 是仅含截距的空模型的对数似然值。

| Pseudo R² 范围 | 拟合评价 |
|---------------|---------|
| < 0.1 | 较差 |
| 0.1 - 0.2 | 一般 |
| 0.2 - 0.3 | 可接受 |
| 0.3 - 0.4 | 良好 |
| > 0.4 | 优秀（但极少见） |

> **关键区别**: OLS 的 R² 可以高达 0.8-0.9（对于好的模型），而 McFadden Pseudo R² 的 0.2-0.4 已经算相当不错。**不要用评价 OLS R² 的标准来评价 Pseudo R²**。

### 8.4 解读 Odds Ratio (OR)

Odds Ratio（几率比）是 Logit 回归中最核心的解释量。理解 OR 是正确使用 Logit 回归的关键。

#### 什么是 Odds

**Odds（几率）** = 事件发生概率 / 事件不发生概率 = `p / (1-p)`

- 如果事件发生概率 p = 0.8，则 odds = 0.8/0.2 = 4.0，即 "发生与不发生的比值为 4:1"。
- 如果 p = 0.5，则 odds = 1.0，即 "发生的可能性与不发生的可能性持平"。

#### 什么是 Odds Ratio

**OR = exp(系数)**，表示自变量每增加一个单位，因变量的 odds 乘以 OR。

- **OR > 1**: 自变量增大会**提高**事件发生的几率（正向影响）
- **OR = 1**: 自变量对事件发生**无影响**
- **OR < 1**: 自变量增大会**降低**事件发生的几率（负向影响）

#### 一个具体例子

假设研究 **教育水平对录取结果的影响**，Logit 回归得到:

| 变量 | 系数 | OR | p 值 |
|------|------|-----|------|
| 本科 (本科=1, 非本科=0) | 0.916 | 2.50 | 0.001 |

**正确解读**:
- 系数 = 0.916: 本科毕业的人，log-odds 比非本科毕业的人高 0.916。
- **OR = 2.50**: 本科毕业的人被录取的 **odds** 是非本科毕业的人的 **2.5 倍**。

假设非本科毕业者的录取概率为 20% (odds = 0.25)，那么本科毕业者的 odds 为 0.25 x 2.5 = 0.625，对应的概率为 0.625 / (1 + 0.625) = 38.5%。

#### 常见误解与澄清

| 误解 | 正确理解 |
|------|---------|
| "OR=2.5 表示录取概率提高了 2.5 倍" | **错**。OR 改变的是 odds，不是概率。 |
| "OR=2.5 表示录取概率提高了 150%" | **错**。概率的绝对增幅取决于基线概率。 |
| "OR 和相对风险是一回事" | **错**。OR 基于 odds 比，相对风险基于概率比。 |
| "OR > 1 就是强效应" | 不一定。OR=1.1 表示 odds 仅增加 10%，效应很小。 |

**实用口诀**: "OR 看方向，不看幅度。" — OR > 1 是正向，OR < 1 是负向；但效应的实际大小需要结合业务场景判断。

### 8.5 Logit 专用图表

Logit 回归提供两种 OLS 所没有的专用图表。

#### ROC 曲线与 AUC

**ROC 曲线**（Receiver Operating Characteristic）展示模型在不同分类阈值下的真阳性率 (TPR) 与假阳性率 (FPR) 的权衡。

图中包含:
- **蓝色实线** — ROC 曲线，左上方越靠近左上角，模型分类能力越强。
- **灰色虚线** — 随机分类器参考线（对角线），表征完全没有分类能力的模型。
- **AUC 标注** — 曲线下面积 (Area Under the Curve)。

**AUC 评判标准**:

| AUC 范围 | 分类能力 |
|---------|---------|
| 0.5 | 无分类能力（等同于随机猜测） |
| 0.5 - 0.6 | 非常差 |
| 0.6 - 0.7 | 较差 |
| 0.7 - 0.8 | 可接受 |
| 0.8 - 0.9 | 优秀 |
| 0.9 - 1.0 | 杰出 |

> **[截图占位]**: ROC 曲线图，蓝色实线明显高于灰色虚线，AUC=0.82 标注在标题和图例中。蓝色区域为曲线下方的填充。

**如何阅读 ROC 曲线**:
- 曲线越贴近**左上角** (0, 1)，模型越好 — 这意味着高 TPR 且低 FPR。
- 曲线贴近**对角线**，说明模型几乎没有分类能力。
- AUC = 0.82 的含义: 随机抽取一个正例和一个负例，模型给正例打出更高预测概率的概率为 82%。

#### OR 森林图

**OR 森林图**（Odds Ratio Forest Plot）将每个自变量的 OR 及其 95% 置信区间以"点-须" (dot-whisker) 形式可视化。

图中包含:
- **蓝色圆点** — p < 0.05 的显著变量的 OR 点估计值
- **灰色圆点** — p >= 0.05 的不显著变量
- **水平须线** — 95% 置信区间
- **灰色垂直虚线** — OR = 1 参考线（无效应线）
- **x 轴为对数刻度** — 使得 OR 的对称性在视觉上更直观

> **[截图占位]**: OR 森林图，纵轴列出变量名（按 OR 绝对值降序），横轴为对数刻度。蓝色和灰色圆点分布在 OR=1 虚线两侧。

**如何阅读森林图**:
- **须线完全在 OR=1 右侧** (OR_low > 1) → 该变量的正向效应在 95% 置信水平上显著。
- **须线完全在 OR=1 左侧** (OR_high < 1) → 该变量的负向效应显著。
- **须线跨越 OR=1** → 该变量的效应在 95% 置信水平上不显著（可能为正也可能为负）。
- 蓝色变量 = 显著 (p<0.05)；灰色变量 = 不显著。

### 8.6 完整案例: 客户流失分析

#### 场景描述

某电信公司希望分析客户流失的影响因素。数据包含 1,000 条客户记录，核心变量包括年龄、月消费额、合同期限、技术支持订阅、性别等。分析目标: 识别导致客户流失的关键因素，并评估模型的分类性能。

#### 步骤 1: 加载数据

1. 在 **数据上传与预览** 页面，加载流失数据集。
2. 检查变量类型 — `churn`（流失）应为二元型，包含值 0 和 1。

**数据快照**:

| churn | age | monthly_charges | tenure | tech_support | gender |
|-------|-----|-----------------|--------|-------------|--------|
| 1 | 42 | 89.50 | 3 | 0 | 1 |
| 0 | 35 | 45.20 | 24 | 1 | 0 |
| 1 | 56 | 120.00 | 1 | 0 | 0 |
| 0 | 28 | 65.00 | 36 | 1 | 1 |
| ... | ... | ... | ... | ... | ... |

#### 步骤 2: 模型设定

1. 切换到 **模型设定** 页面。
2. 选择 `churn` 为因变量。应用自动检测到二分类变量，弹出蓝色信息框建议使用 Logit 模型。
3. 将模型类型切换为 **Logit**。
4. 自变量勾选: `age`、`monthly_charges`、`tenure`、`tech_support`、`gender`。
5. 公式预览显示: `churn ~ age + monthly_charges + tenure + tech_support + gender`
6. 点击 **运行回归**。

**预期结果**: 显示 "回归模型运行成功！"，Logit 模型统计量展示 Pseudo R² 和 LR 检验结果。

#### 步骤 3: 解读系数与 OR

回归结果系数表（示例数值）:

| 变量 | 系数 | OR | z 值 | p 值 | 显著性 |
|------|------|-----|------|------|--------|
| Intercept | -1.203 | 0.300 | -4.52 | <0.001 | *** |
| age | 0.028 | 1.028 | 3.21 | 0.001 | ** |
| monthly_charges | 0.015 | 1.015 | 5.67 | <0.001 | *** |
| tenure | -0.082 | 0.921 | -7.34 | <0.001 | *** |
| tech_support | -1.451 | 0.234 | -8.91 | <0.001 | *** |
| gender | 0.103 | 1.108 | 1.15 | 0.250 | 不显著 |

**解读要点**:

1. **`tech_support` (OR=0.234, p<0.001)**: 这是影响最显著的变量。订阅了技术支持服务的客户，其流失的 odds 仅为未订阅者的 23.4%。这意味着技术支持是强有力的保留因素。

2. **`tenure` (OR=0.921, p<0.001)**: 合同期限每增加 1 个月，流失的 odds 乘以 0.921（即下降约 7.9%）。长期客户更不容易流失 — 符合预期。

3. **`monthly_charges` (OR=1.015, p<0.001)**: 月消费额每增加 1 单位，流失 odds 增加 1.5%。高消费客户流失风险更高，但效应相对较小。

4. **`age` (OR=1.028, p=0.001)**: 年龄每增加 1 岁，流失 odds 增加约 2.8%。

5. **`gender` (OR=1.108, p=0.250)**: OR 的 95% 置信区间跨越 1，不显著。性别对流失无统计显著影响。

#### 步骤 4: 查看模型统计量

| 指标 | 值 | 解读 |
|------|-----|------|
| Pseudo R² (McFadden) | 0.31 | 模型拟合良好 |
| Log-Likelihood | -345.20 | — |
| AIC | 702.40 | 可用于与其他模型比较 |
| BIC | 731.85 | 考虑参数个数的惩罚项 |
| LR chi2 | 310.46 | 似然比检验统计量 |
| LR p-value | <0.001 | 模型整体高度显著 |

#### 步骤 5: 评估 ROC 曲线

切换到 **回归结果** 页面，查看 **ROC 曲线**:

**预期 AUC ≈ 0.82** — 属于"优秀"分类能力。说明模型能较好地区分流失与留存客户。

> **[截图占位]**: 客户流失案例的 ROC 曲线，AUC=0.82。蓝色曲线明显偏离灰色对角线，向 (0, 1) 左上角弯曲。

**业务意义**: AUC=0.82 意味着随机从流失客户和留存客户中各抽取一位，模型有 82% 的概率能正确判断哪位是流失客户。这足以支持业务决策（如定向优惠挽留高风险客户）。

#### 步骤 6: 查看 OR 森林图

展开 **OR 森林图**，直观对比各变量的效应方向和大小:

- `tech_support` 的须线完全在 OR=1 左侧 → **显著的保护因素**（蓝色圆点）
- `tenure` 的须线也在 OR=1 左侧 → **显著的保护因素**（蓝色圆点）
- `monthly_charges` 和 `age` 的须线在 OR=1 右侧 → **显著的风险因素**（蓝色圆点）
- `gender` 的须线跨越 OR=1 → **不显著**（灰色圆点）

#### 业务建议总结

基于 Logit 回归结果，客户保留策略应优先关注:
1. **推广技术支持服务** — 订阅技术支持的客户流失风险降低 77% (OR=0.234)。
2. **关注高月消费客户** — 每增加消费额，流失风险微增，需配合增值服务提升粘性。
3. **延长合同期限** — 长期客户更稳定，通过合约优惠鼓励续约。
4. **年龄和性别不在优先事项** — 年龄效应小，性别不显著。

### Logit 常见问题

#### Q: Logit 回归的因变量必须是 0 和 1 吗？
A: 是的。工具要求因变量取值为 0（未发生）和 1（发生）。如果你的数据使用其他编码（如 "yes"/"no" 或 1/2），请先在上传前进行编码转换。

#### Q: Pseudo R² = 0.15 算好还是坏？
A: 对 Logit 模型来说，McFadden Pseudo R² = 0.15 属于"一般"到"可接受"范围（见上文 8.3 节的评判标准）。在很多社会科学和商业应用中，0.1-0.3 是正常范围。不要用 OLS R² 的标准来评判。

#### Q: Logit 模型可以像 OLS 一样添加交互项吗？
A: 可以。在模型设定页面的变量转换区域添加交互项。但需注意: Logit 模型的交互效应解读比 OLS 更复杂，不能直接从交互项的 OR 判断方向。

#### Q: Logit 模型收敛失败怎么办？
A: 如果模型报错 "failed to converge"，可能的原因:
- **完全分离** (perfect separation): 某个自变量完美预测因变量。解决方案: 移除该变量或使用惩罚回归。
- **多重共线性**: 自变量高度相关。检查相关系数矩阵，移除冗余变量。
- **样本量不足**: Logit 模型对样本量的要求高于 OLS。建议每个自变量至少有 20 个事件（即至少 20 个 1）。

#### Q: 多分类因变量（如 3 个类别）可以用 Logit 吗？
A: 本工具当前的 Logit 引擎仅支持**二分类** Logit。有序多分类 (ordinal) 和多项 Logit (multinomial) 将作为后续版本的计划功能。
