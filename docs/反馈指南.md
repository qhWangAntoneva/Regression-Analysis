## 反馈渠道

所有反馈通过 GitHub Issues 提交：

> https://github.com/qhWangAntoneva/Regression-Analysis/issues

点击页面右上角的绿色 **New Issue** 按钮，选择合适的模板开始提交。

**当前可用模板**：
- **Bug 报告** (`bug_report.md`) — 用于报告程序错误、崩溃、计算结果异常
- **功能建议** (`feature_request.md`) — 用于建议新功能、改进现有功能

请在提交前使用模板中提供的结构填写，这将帮助我们快速理解和处理你的反馈。

### 好的功能建议示例

```
### 功能描述
支持逻辑回归（Logistic Regression），用于分析二分类因变量

### 使用场景
我是一名社科研究生，经常分析"是否参加培训"、"是否就业"等0/1结果的问卷数据。目前用 SPSS 做逻辑回归，但 SPSS 的图表和界面体验较差，希望能在这个工具里完成完整分析流程。

### 建议的实现方式
- 在模型控制面板添加"模型类型"下拉选择（OLS / Logit / Probit）
- 选择 Logit 后自动使用逻辑回归引擎
- 结果展示中增加 OR（比值比）列
- 诊断图替换为 ROC 曲线和混淆矩阵

### 替代方案
目前是导出数据到 SPSS 做逻辑回归，回到工具做描述性统计，流程割裂。

### 是否愿意参与测试
是
```

## 响应时间预期

为了帮助你了解反馈处理的节奏，以下是我们的一般响应时间：

| 反馈类型 | 初次响应 | 预期处理时间 |
|---------|---------|------------|
| **P0 严重 Bug**（数据丢失、结果严重错误） | 24 小时内 | 3-7 天修复 |
| **P1 重大 Bug**（功能无法使用但有替代方案） | 48 小时内 | 1-2 周修复 |
| **P2 次要 Bug**（显示异常、体验问题） | 1 周内 | 视优先级排期 |
| **功能建议** | 1 周内 | 评估后纳入版本规划 |

**注意事项**：

- 以上时间基于维护者兼职维护的前提，可能因实际情况浮动
- P0/P1 Bug 将在修复后尽快发布补丁版本（如 v1.0.1）
- 功能建议会在被采纳后纳入 v1.1+ 版本规划
- 重大功能建议可能需要较长时间，请耐心等待
- 请关注 GitHub Issues 中的标签更新和回复通知

## 反馈前自查清单

在提交反馈之前，请快速检查以下事项，这能节省你的时间并避免重复提交：

### Bug 报告自查

- [ ] 确认使用的是最新版本（启动应用时左下角可见版本号）
- [ ] 重新启动应用后问题是否仍然存在
- [ ] 检查 `docs/已知问题.md` 是否已记录了此问题
- [ ] 在 GitHub Issues 中搜索，确认没有其他人已报告相同问题
- [ ] 准备一个**最小可复现示例**（数据集越小越好）
- [ ] 记录复现步骤，确保他人能按步骤重现

### 功能建议自查

- [ ] 在 GitHub Issues 中搜索，确认没有重复建议
- [ ] 描述你的**具体使用场景**而不仅仅是"想要 XX 功能"
- [ ] 考虑这个功能对 3 种用户画像（社科研究生、市场研究员、政策分析师）中的哪些人有用
