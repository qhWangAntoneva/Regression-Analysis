## 架构概览

```
┌─────────────────────────────────────────────────┐
│  Presentation Layer                              │
│  app/pages/*.py  +  app/components/*.py          │
│  (Streamlit UI: 页面 + 可复用组件)               │
├─────────────────────────────────────────────────┤
│  Application Layer                               │
│  st.session_state  (跨页面通信 + 状态管理)        │
├─────────────────────────────────────────────────┤
│  Business Logic Layer                            │
│  src/  (data_io / preprocessing / modeling /     │
│          results / visualization / export)        │
├─────────────────────────────────────────────────┤
│  Data Layer                                      │
│  文件系统 (上传 / 导出 / 会话缓存)                │
└─────────────────────────────────────────────────┘
```

### 设计原则

1. **关注点分离**: UI 组件 (`app/`) 不包含业务逻辑；业务模块 (`src/`) 不依赖 Streamlit。
2. **引擎抽象**: 回归引擎通过统一接口适配，方便未来替换或扩展。
3. **结果标准化**: 所有引擎输出统一的 `ModelResult` 数据结构。
4. **渐进增强**: 每个模块通过 `try/except ImportError` 实现可选依赖，缺失时优雅降级。

### 1. Presentation Layer — `app/`

**页面 (pages/)**:

| 文件 | 页面名称 | 核心功能 |
|------|---------|---------|

### 4. Data Layer — 文件系统

- **上传**: Streamlit `UploadedFile` → `tempfile.NamedTemporaryFile` → 解析后删除临时文件
- **导出**: `io.BytesIO` → `st.download_button` 触发浏览器下载
- **会话缓存**: JSON 序列化到 `.session_cache`，启动时自动检测恢复
- **示例数据**: 内存中通过 numpy/pandas 实时生成，不依赖外部文件

## 如何添加新的回归引擎

以添加 `LogisticRegression` 引擎为例:

### 步骤 1: 创建引擎适配器

在 `src/modeling/engines/` 下创建新文件，如 `sklearn_engine.py`:

```python
# src/modeling/engines/sklearn_engine.py
from src.modeling.specification import ModelSpec
from src.results.table import ModelResult, CoefficientRow

def run_logistic(data, spec, **kwargs) -> ModelResult:
    """使用 sklearn LogisticRegression 拟合模型。"""
    from sklearn.linear_model import LogisticRegression
    # ... 数据准备、拟合计 ...
    return ModelResult(
        model_type="LogisticRegression",
        coefficients=[...],
        ...
    )
```

### 步骤 2: 适配统一接口

引擎函数应接受 `(data: pd.DataFrame, spec: ModelSpec, **kwargs)` 并返回 `ModelResult`。

`ModelSpec` 的关键属性:
- `dep_var`: 因变量名
- `indep_vars`: 自变量名列表
- `has_intercept`: 是否包含截距
- `transforms`: `{var_name: transform_type}` — 变量转换映射
- `interaction_terms`: `[(var1, var2), ...]` — 交互项列表

### 步骤 3: 在结果页面集成

在 `app/pages/03_model_spec.py` 的 `_run_regression()` 中添加引擎选择逻辑:

```python
engine = model_config.get("engine", "ols")
if engine == "ols":
    result = run_ols(df, spec, cov_type=cov_type)
elif engine == "logistic":
    result = run_logistic(df, spec)
```

### 步骤 4: 在 UI 中添加引擎选择器

在 `app/components/model_control.py` 的 `render_model_controls()` 中添加:

```python
engine = st.selectbox("回归引擎", options=["ols", "logistic"], key="engine_type")
model_config["engine"] = engine
```

### 步骤 5: 编写测试

在 `tests/unit/` 下创建 `test_sklearn_engine.py`:

```python
def test_logistic_basic(sample_df):
    spec = ModelSpec(dep_var="y", indep_vars=["x1", "x2"])
    result = run_logistic(sample_df, spec)
    assert result.model_type == "LogisticRegression"
    assert len(result.coefficients) > 0
```

## 如何添加新的导出格式

以添加 "Markdown 表格导出" 为例:

### 步骤 1: 创建渲染器

在 `src/export/` 下创建文件:

```python
# src/export/markdown_renderer.py

class MarkdownRenderer:
    @staticmethod
    def render_single(result):
        """将系数表渲染为 Markdown 表格。"""
        lines = ["| 变量 | 系数 | 标准误 | t值 | p值 |",
                 "|------|------|--------|-----|------|"]
        for c in result.coefficients:
            lines.append(f"| {c.name} | {c.coef:.4f} | {c.se:.4f} | {c.t_stat:.4f} | {c.pvalue:.4f} |")
        return "\n".join(lines)
```

### 步骤 2: 在导出页面中添加

在 `app/pages/06_export.py` 的 `render()` 中添加新区域:

```python
st.subheader("Markdown 表格导出")
if model_result is not None:
    from src.export.markdown_renderer import MarkdownRenderer
    md_content = MarkdownRenderer.render_single(model_result)
    st.download_button(
        label="下载 Markdown (.md)",
        data=md_content.encode("utf-8"),
        file_name="regression_table.md",
        mime="text/markdown",
    )
```

### 步骤 3: 添加到综合导出

在 `_export_all_results()` 函数中追加新的导出文件到 ZIP 包。


1. 使用 `conftest.py` 中的 fixture 而非自己生成数据
2. 每个公开函数至少测试正常路径 + 1 个错误路径
3. 可视化函数测试图形对象的结构（非像素级对比）
4. 导出函数测试字节流非空 + 格式正确

## 编码规范

### Python 编码

1. **编码声明**: 所有 `.py` 文件首行为 `# encoding: utf-8`
2. **类型注解**: 使用 `from __future__ import annotations` + 完整类型注解
3. **Lazy imports**: UI 组件和页面使用 `try/except ImportError` 包裹，避免缺失依赖时崩溃
4. **绝对导入**: 始终使用 `from src.xxx import ...`，不使用相对导入
5. **Docstring**: 使用 Google 风格 docstring (Args/Returns/Raises)
6. **文件操作**: 所有 `open()` 必须显式 `encoding='utf-8'`

### Streamlit 页面规范

1. 页面入口为文件底部的 `render()` 调用
2. 使用 `st is None` 守卫（避免非 Streamlit 环境崩溃）
3. 页面间通过 `st.page_link` 而非硬编码路径跳转
4. 错误处理: 使用 `st.error(f"描述: {e}")` 而非裸异常

### 引擎适配器规范

1. 签名: `(data: pd.DataFrame, spec: ModelSpec, **kwargs) -> ModelResult`
2. 输出: 必须返回 `ModelResult` 对象
3. 错误: 抛出描述性异常，由 UI 层捕获并显示
4. 依赖: 使用 lazy import 避免硬依赖

### Git 提交规范

- 提交信息: `<type>: <description>` (如 `feat:`, `fix:`, `docs:`, `test:`)
- 提交前运行全部测试
- 提交后立即 push
