## 规划总览

v1.1 的目标是将工具从"纯 OLS 线性回归工具"升级为"多模型回归分析平台"。新功能按优先级分为三个等级，高优先级功能聚焦于扩展模型类型覆盖，中优先级聚焦于高级分析和诊断，低优先级聚焦于部署和运维改进。

## 高优先级 (★★★)

目标版本: **v1.1** | 预计发布: v1.0 后 8-10 周

### 1. 逻辑回归 / Probit 支持

**预计工作量**: 3-4 周

**功能描述**：
支持二分类因变量的逻辑回归 (Logit) 和 Probit 模型，为社科研究生和医学研究者提供分类结果分析能力。

**具体任务**：

| 任务 | 工作量 | 说明 |
|------|--------|------|
| 新增 `statsmodels Logit/Probit` 适配器 | 3 天 | 仿照现有 `statsmodels_engine.py` 的 OLS 适配器模式，抽取公共接口 |
| `ModelResult` 扩展 | 2 天 | 增加 OR（比值比）、对数似然比检验结果等字段 |
| 模型选择 UI | 2 天 | 模型控制面板新增"模型类型"下拉（OLS / Logit / Probit），按类型动态调整选项 |
| 诊断图适配 | 3 天 | ROC 曲线 + 混淆矩阵 + 分类准确率报告 |
| 结果展示适配 | 2 天 | 系数表增加 OR 列 + 95% CI（对数似然方法） |
| 测试与文档 | 1 周 | 50+ 测试用例，更新用户手册新增案例 |

**关键挑战**：
- `ModelResult` 目前设计围绕 OLS，需重构为多模型泛型结构
- patsy 分类变量编码逻辑需验证与 Logit/Probit 的兼容性

---

### 2. 多层次模型 (MixedLM)

**预计工作量**: 3-4 周

**功能描述**：
支持混合效应模型（Mixed Linear Model），允许用户为面板数据或嵌套数据指定随机效应项（随机截距/随机斜率），为政策分析师和教育研究者提供层级数据分析能力。

**具体任务**：

| 任务 | 工作量 | 说明 |
|------|--------|------|
| `statsmodels MixedLM` 适配器 | 3 天 | 新增 `mixed_engine.py`，处理公式中的随机效应语法（`~ C(group)`） |
| 随机效应选择 UI | 3 天 | 变量选择器新增"随机效应"字段（分组变量选择 + 随机截距/斜率选项） |
| 结果展示 | 3 天 | 固定效应系数表 + 随机效应方差分量表 + 组内相关系数 (ICC) |
| 诊断图 | 2 天 | Q-Q 图（随机效应）, 残差分面图（按组） |
| `ModelResult` 扩展 | 2 天 | 增加 `random_effects_df`, `variance_components`, `icc` 字段 |
| 测试与文档 | 1 周 | 40+ 测试用例（含教材经典案例如 sleepstudy），更新用户手册 |

**关键挑战**：
- 随机效应语法需要与 patsy 公式妥善交互
- 随机斜率模型的截面/面板数据适配
- `ModelResult` 泛型化与本功能高度重叠，建议与逻辑回归一起进行

---

### 3. 分析快照

**预计工作量**: 2 周

**功能描述**：
允许用户将当前分析状态（数据配置 + 模型规格 + 结果）保存为 JSON 快照文件，后期可一键恢复。类似于 PhotoShop 的历史记录，但不是步骤回溯，而是完整状态保存。

**具体任务**：

| 任务 | 工作量 | 说明 |
|------|--------|------|
| `AnalysisSnapshot` 数据结构设计 | 2 天 | 设计快照 JSON schema（数据子集引用、变量选择、模型结果、图表配置） |
| 快照保存 | 2 天 | 序列化当前 session_state 到 JSON，含数据子集路径（避免重复存储完整数据） |
| 快照加载/恢复 | 2 天 | 从 JSON 反序列化恢复 session_state，验证数据一致性 |
| 快照管理 UI | 2 天 | 侧边栏新增"分析历史"区域，列出已保存快照，支持加载/删除/导出 |
| 测试与集成 | 2 天 | 20+ 测试用例 |

**与现有持久化的关系**：
- 现有 `.session_cache` 是自动崩溃恢复（单文件，仅最新状态），仅用于防止误关浏览器
- 快照是用户主动保存的版本历史（多文件，可选择保留），用于对比不同模型设定
- 两者共存互补，不相互替代

## 中优先级 (★★☆)

目标版本: **v1.2** | 预计发布: v1.1 后 8-12 周

### 4. 面板数据模型

**预计工作量**: 3-4 周

**功能描述**：
支持面板数据的固定效应 (Fixed Effects) 和随机效应 (Random Effects) 模型，适用于经济学和政策分析领域的 multi-period 数据。

**具体任务**：
- `statsmodels PanelOLS` / `RandomEffects` 适配器
- 面板数据识别（自动检测个体变量 + 时间变量组合）
- Hausman 检验（FE vs RE 选择建议）
- 面板数据格式验证（非平衡面板警告）
- 组内/组间/总体 R-squared 增量报告

**依赖**: 多层次模型的经验可复用（随机效应的 UI 和结果展示模式）

---

### 5. 贝叶斯回归

**预计工作量**: 3-4 周

**功能描述**：
引入贝叶斯线性回归，使用 PyMC 或 Bambi 作为后端，提供后验分布、可信区间和先验设置界面。

**具体任务**：
- PyMC / Bambi 适配器（从 statsmodels 公式接口映射到 Bambi）
- 先验分布设置 UI（normal / student-t / flat prior 选项）
- 后验摘要表（均值、标准差、HDI 区间、R-hat 诊断）
- 后验分布图（trace plot + posterior density）
- MCMC 采样进度指示

**关键挑战**：
- PyMC/Bambi 可能增加较重的依赖（MCMC 编译），建议设为可选依赖
- 采样时间不可预测，需进度反馈

---

### 6. 边际效应图

**预计工作量**: 1-2 周

**功能描述**：
生成关键自变量的边际效应图（Marginal Effects Plot），在控制其他变量不变的情况下展示单一变量对因变量的边际影响。

**具体任务**：
- `marginal_effects()` 函数（基于 predict + 变量网格）
- 连续变量边际效应图（线图 + 置信区间带）
- 分类变量边际效应图（点估计 + 误差棒）
- 多模型对比边际效应（同一图上叠加不同模型）

**适用场景**：交互项解释、非线性变换后的变量解读、政策效果可视化

---

### 7. 工具变量回归 (IV Regression)

**预计工作量**: 2-3 周

**功能描述**：
支持工具变量两阶段最小二乘法 (2SLS)，用于处理内生性问题。适用于经济学和社科研究中存在遗漏变量偏误的场景。

**具体任务**：
- `statsmodels IV2SLS` 适配器
- 第一阶段回归结果展示（工具变量有效性检验）
- Wu-Hausman 内生性检验
- 弱工具变量检验（第一阶段 F > 10 规则 + Stock-Yogo 临界值）
- 工具变量选择 UI（分别选择内生变量和工具变量）

## 低优先级 (★☆☆)

目标版本: **v1.3** | 预计发布: v1.2 后 8-12 周

### 8. Docker 部署

**预计工作量**: 1-2 周

**功能描述**：
提供 Dockerfile 和 docker-compose.yml，支持一键容器化部署。降低环境配置门槛，让非 Python 用户也能快速使用。

**具体任务**：
- 编写 `Dockerfile`（基于 Python 3.12-slim，安装所有依赖）
- 编写 `docker-compose.yml`（挂载数据卷、端口映射）
- 验证 Streamlit 在容器内的 WebSocket 连接
- 编写 `docs/Docker部署指南.md`

---

### 9. 中介效应 / 调节效应分析

**预计工作量**: 2-3 周

**功能描述**：
支持三步骤中介检验（Baron-Kenny 方法）和 Sobel 检验，以及 Bootstrap 置信区间方法。

**具体任务**：
- 中介效应检验引擎（M → DV 与 IV+M → DV 的两步回归）
- Sobel 检验 + Bootstrap CI
- 中介效应路径图可视化

---

### 10. 正则化回归 (Ridge / Lasso / Elastic Net)

**预计工作量**: 2-3 周

**功能描述**：
引入 scikit-learn Ridge/Lasso/ElasticNet，处理高维数据和严重多重共线性问题。

**具体任务**：
- scikit-learn 适配器（Ridge / Lasso / ElasticNet）
- 正则化参数 lambda 的交叉验证选择（RidgeCV / LassoCV）
- 正则化路径图（系数随 lambda 变化的轨迹）
- 系数表（对比 OLS vs Ridge vs Lasso）

---

### 11. Bootstrap 标准误

**预计工作量**: 1 周

**功能描述**：
提供 Bootstrap 重抽样标准误计算，作为稳健标准误 (HC0-HC3) 的补充选项。

**具体任务**：
- Bootstrap 标准误引擎（可配置 B 次重抽样）
- 结果展示（与原标准误对比列）
- 进度条 + 可取消（大 B 值下耗时较长）

---

### 12. 用户历史管理

**预计工作量**: 2 周

**功能描述**：
记录用户的分析历史（数据集、模型设定、结果），支持按日期浏览、搜索和比较历史分析。

**具体任务**：
- SQLite 历史数据库（替代当前 JSON 文件持久化）
- 历史浏览 UI（时间线视图）
- 历史搜索（按数据集名称、变量名、模型类型）
- 历史对比（挑选两个历史分析结果并排比较）

## 版本里程碑与时间线

```
v1.0 发布 ──────► v1.1 ──────────► v1.2 ──────────► v1.3
  (当前)          (~8-10周)        (~16-22周)       (~24-34周)

v1.1 内容:                    v1.2 内容:                  v1.3 内容:
  ├─ 逻辑回归/Probit             ├─ 面板数据模型             ├─ Docker 部署
  ├─ 多层次模型(MixedLM)         ├─ 贝叶斯回归               ├─ 中介/调节效应
  ├─ 分析快照                    ├─ 边际效应图               ├─ 正则化回归
  └─ ModelResult 泛型重构       ├─ 工具变量回归             ├─ Bootstrap SE
                                  └─ (+ v1.1 bugfix)         └─ 用户历史管理
```

### 版本发布策略

| 属性 | 策略 |
|------|------|
| 发布节奏 | 功能驱动，非时间驱动（一个优先级级别的功能全部完成后发布） |
| 补丁版本 (v1.0.x) | P0/P1 Bug 修复，随时发布 |
| 小版本 (v1.x) | 完成一个优先级的所有功能后发布 |
| 大版本 (v2.0) | 架构重大变更时考虑（当前无计划） |

### 风险与依赖

| 风险 | 影响 | 缓解 |
|------|------|------|
| `ModelResult` 泛型重构工作量被低估 | 阻塞 v1.1 所有新模型类型 | v1.1 开工前先完成重构并独立验证 |
| PyMC/Bambi 依赖过重 | v1.2 贝叶斯功能延期 | 将贝叶斯设为可选依赖，v1.2 可按需降级 |
| 用户反馈驱动优先级变更 | 需求栈顺序改变 | 每个版本发布后重新评估下版本优先级 |
| 单人维护时间不足 | 所有功能延期 | 优先核心功能，非核心功能可降级或舍弃 |
